# Соглашения по коду

Канон продукта: [AGENTS.md](../AGENTS.md). Архитектура backend: [ARCHITECTURE.md](ARCHITECTURE.md). Этот файл — единый кодстайл. Не Java-OOP и не глобальный mutable-state.

## Общее

- Идентификаторы на английском, тексты интерфейса на русском.
- Не выдумывать статусы заявок, цены, роли, юридичку.
- Секреты не коммитить и не печатать.
- Live Bitrix / 1C / Telegram — только по явной просьбе владельца.

## Go

- Зависимости только `adapters → application → domain`.
- Domain: структуры + методы инвариантов, без Fiber/SQL/env.
- Application: сценарии через порты. Конфиг целиком в сервис не тащить — только нужные поля в конструктор.
- HTTP handler: разобрать запрос → вызвать сервис → DTO. Один `MapError`, `errors.As`.
- Порт — маленький интерфейс у потребителя. `noop`-адаптеры нормальны до Stage live-интеграций.
- Инструменты: `gofmt`, `go test ./...`, `go vet ./...`.

## TypeScript / Next.js

- Frontend — клиент API и UX-валидация, не доменная машина состояний.
- Один HTTP-слой: `lib/api/client.ts` (`requestJson`, `ApiError`). DTO на границе — snake_case.
- Server Components по умолчанию; `"use client"` только для форм, меню, браузерных API.
- Брейкпоинт десктоп-шапки: `DESKTOP_MIN_WIDTH_PX` в `lib/breakpoints.ts` (= Tailwind `lg` = 1024). Менять CSS шапки и `matchMedia` только вместе.
- Токены цвета — `globals.css` (`brand-*`). Не плодить новые палитры в JSX.

## Переиспользование

- Оболочка страницы, сетка туров, ошибка формы — общие компоненты, не копия классов.
- Контакты и имя сайта — только `site-config.ts` (реэкспорт в `contact.ts` допустим).
