v3 заморожен. Новые фичи и долг — сюда. **Этап 1 обязателен и идёт первым:** баги, следы ИИ в коде, безопасная оптимизация. ИИ-звонки и ИИ-продавец — **поздние** этапы, не этап 1.

Правила те же, что в v3:

- Не выдумывать цены, юридичку, тексты туров, статусы заявок.

- Live Bitrix24 / 1С и живой эквайринг — только по явной просьбе владельца.
- Telegram-уведомления на проде не выключать.
- Секреты только в gitignored `.env.production`. Несекретные поля сайта — админка «Настройки».
- Не делать линкфармы, фейковые отзывы, покупные биржи ссылок.

## Этап 1 — баги, следы ИИ, оптимизация

Первый обязательный шаг v4. Без новых продуктовых фич и без выдуманных бизнес-правил.

Сделано в коде этапа 1:

- Удалена мёртвая форма `telegram-settings-form` (админка давно на канале+адресе).
- `.env.example` / `.env.production.example` без дублей OAuth и без «Stage E»; пустые плейсхолдеры и ссылки на доки.
- Compose прокидывает `OPERATOR_*` и `NEXT_PUBLIC_OPERATOR_*` (пустые = плейсхолдеры в коде).
- Worker получает `PUBLISHER_*` (due SMM) и `BACKUP_LAST_PATH` (watchdog).
- Из compose убран неиспользуемый `GOOGLE_CLIENT_*` (кнопка Google скрыта).
- В «Настройках» явная памятка: секреты и Метрика только env, не вторая правда в БД.

Дальше по этапу 1 — только доказуемые баги (тесты, битые ссылки, leftover goose). Не «чинить» цену регулярного тура и не вводить `AWAITING_PAYMENT`.

Проверки: `cd backend && go test ./... && go vet ./...` · `cd frontend && npm run lint && npm run build`.

## Definition of Done

- Решение владельца, не догадка
- Логика в domain/application, канал — адаптер
- Секреты в env, несекретное — «Настройки», если ключ уже в модели
- Тесты `go test` / `go vet` / `npm run lint` / `npm run build`
- Прод — только по просьбе; Postgres не сбрасывать
- Этап 1 не подменяет этапы 7–8
