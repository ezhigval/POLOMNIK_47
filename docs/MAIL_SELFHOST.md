# Свой MX на ВМ (пересылка `info@` в админку)

Запрос владельца: не Яндекс 360, а почтовый приём **на нашем сервере**, который все входящие на `info@tikhvin-palomnik.ru` пересылает на адреса из админки **Настройки → Пересылка почты**.

Это **не то же самое**, что уже есть в коде.

---

## Что уже есть и чего нет

| Есть | Нет |
|------|-----|
| Поле `mail_forward_to` в админке (до 20 адресов) и запасной `MAIL_FORWARD_TO` в env | Приём писем из интернета (на ВМ нет SMTP на порту 25) |
| Mailer сайта (`MAIL_ADAPTER=smtp`) — исходящие: регистрация, сброс пароля | Код **не** читает `mail_forward_to` при отправке и **не** принимает входящие |
| DNS MX сейчас: `mail.tikhvin-palomnik.ru` | A/CNAME у `mail.` **нет** — входящие сейчас никуда не доходят |

Сайт и API слушают 80/443. Письмо «на info@» приходит на **MX-хост порта 25**, это другой сервис.

---

## Главный стоппер: Yandex Cloud и порт 25

ВМ в **Yandex Cloud**. Официально: с публичного IP **исходящий TCP 25 закрыт**, кроме серверов Яндекс.Почты. [FAQ VPC](https://yandex.cloud/en/docs/vpc/qa/).

Следствие:

- Принять письмо на 25 (если открыть inbound в security group) — часто можно.
- **Переслать** его на Mail.ru / Gmail / корпоративный MX по порту 25 — **нельзя**, пока поддержка YC не выдаст адрес с открытым 25 (часто **новый** IP → придётся менять A `@` / `www` / `api`).
- Пересылка только на ящики `@yandex.ru` по 25 может пройти (исключение в политике).
- Обход без смены IP: принять у себя, а наружу уйти через **смархост 587/465** (личный Яндекс, Yandex Cloud Postbox, другой SMTP). Тогда «свой MX» есть, но исходящая пересылка всё равно через чужой SMTP.

Без открытого 25 или без смархоста свой пересыльщик на этой ВМ **не заработает**.

---

## Что нужно от владельца (не код)

1. **Решение по исходящим:**  
   - тикет в поддержку Yandex Cloud: IP с открытым 25 + PTR (`mail.tikhvin-palomnik.ru`); если дадут новый IP — обновить A в REG.RU; **или**  
   - смархост на 587 (аккаунт/Postbox) только для релэя пересылки.
2. **Security group** ВМ: inbound **TCP 25** (сейчас снаружи должны быть 22/80/443). Не открывать 25 в интернет как open relay.
3. **DNS (REG.RU)**, A сайта не ломать:

   | Запись | Значение |
   |--------|----------|
   | A `mail` | `93.77.165.81` (или новый IP после тикета) |
   | MX `@` | `mail.tikhvin-palomnik.ru.` приоритет 10 (старый MX без A удалить/заменить) |
   | TXT `@` SPF | `v=spf1 ip4:ЭТОТ_IP ~all` (если релэй через Яндекс — добавить `include:_spf.yandex.net`) |
   | DKIM | свой ключ на `mail._domainkey`, если письма **переотправляем** (не чистый forward) |

4. **PTR** на IP (просится в том же тикете YC). Без PTR чужие серверы часто кладут пересылку в спам.
5. Адреса в админке **Пересылка почты** — реальные ящики, куда слать. Сейчас поле только хранится.
6. Место на диске и антиспам: открытый MX собирает мусор. На той же 2 vCPU ВМ, что сайт, это риск (очередь, блэклист IP, жалобы → YC может заблокировать адрес).

Не делегировать NS зоны на Яндекс и не снимать A `@` / `www` / `api`.

---

## Что нужно в продукте (когда облако и DNS готовы)

Отдельный этап, не смешивать с OAuth:

1. SMTP-приёмник на хосте или в compose (обычно **Postfix**, не Fiber): только домен `tikhvin-palomnik.ru`, ящик `info@`, **не** open relay.
2. Карта пересылки: `info@` → список из `site_settings.mail_forward_to` (fallback `MAIL_FORWARD_TO`). При сохранении настроек — пересобрать aliases и `postfix reload`.
3. Исходящий релэй: либо прямой 25 (после тикета YC), либо `relayhost` на 587.
4. TLS на `mail.` (отдельный сертификат, не путать с Caddy сайта).
5. Минимальный антиспам (хотя бы reject без SPF/очевидный мусор), лимиты, логи.
6. Исходящие сайта (сброс пароля) — по-прежнему `MAIL_ADAPTER=smtp` на 587; это другой контур, его можно оставить через смархост даже при своём MX.

Код приложения **не** должен стать почтовым сервером: логика списка получателей уже в domain (`NormalizeMailForwardList`), адаптер только отдаёт карту Postfix или локальному MTA.

## Рекомендация

Для задачи «всё входящее на `info@` уезжает на личные ящики» надёжнее **ящик в Яндекс 360 + пересылка в кабинете почты**, а поле в админке оставить как список «куда ещё копии с сайта». Свой MX на этой ВМ имеет смысл только если сознательно берёте тикет YC / смархост, PTR, антиспам и риск блэклиста.

Делать приёмник в коде **не начинаем**, пока не будет явного «открываем 25 / такой-то смархост» — иначе сервис встанет и письма пропадут.

Сверка с вариантом Яндекс 360: [MAIL_DNS.md](MAIL_DNS.md).
